# AGENT.md — how to work on this repository

This file is for any agent (human or AI) that changes code, data rules or docs here. `CLAUDE.md` points here.
User-facing text, docs under `docs/` and commit messages are in Spanish (Peru); this file is in English because it
is read by tools as much as by people.

The project publishes ENSO (El Niño–Southern Oscillation) indices and hazard alerts for Peru. A wrong number or a
missed alert on the site is worse than a crash in CI: **correctness of the data comes before everything else**, then
clear failure, then usability.

## 1. The standard every change is held to

For every feature and every decision:

1. **Ask what the best expert in that field would do**, and look it up: the authoritative source (NOAA CPC, ENFEN
   Nota Técnica, IGP, NCEI papers, WMO guidance, WCAG, NIST, the tool's own docs), the preponderance of published
   research, or a measured benchmark. Cite it in the PR or the doc that records the decision.
2. **Ask why that expert would reject your current choice.** If you can name the reason, don't make the choice.
3. **Optimize for what the expert would judge correct** (the evidence-based benchmark or the feasible ideal), never
   for what satisfies the stated constraints most cheaply.
4. **State every trade-off** in the PR description and, if it lasts, in `docs/`. A trade-off that is absorbed
   silently is a bug report waiting to be written.

Focus areas, in order: methodological and scientific correctness (index definitions, base periods, units,
thresholds, provenance), state-of-the-art practice, then usability, intuitiveness of the user flow and
quality-of-life features (freshness and provenance visible, uncertainty labelled, accessible, works on a phone).

## 2. Rounds: plan, pre-execute, implement, retrospect

Each task is done in rounds. **Every round ends with a test that would fail without that round's change.**

| Round | What happens | Exit criterion (a test) |
|---|---|---|
| 0. Preamble | Restate the goal, list the sources, files and data it touches, and the failure modes already seen (section 6). | A failing test or reproduction of the problem, or a written reason why none can exist. |
| 1. Pre-execution | Prototype **at least two alternative routes** in a scratch worktree and *measure* them (correctness against real fixtures, runtime, footprint, how they fail). Record why the losers lose, with the expert objection. | A comparison table in the PR; the chosen route's test passes in the prototype. |
| 2. Implement | The chosen route, smallest coherent diff. Real fixtures, not invented ones, wherever a real response exists. | New tests pass; the full suite passes. |
| 3. Red team | **Every analysis and every design decision, always**: name the alternatives, then at least **5 ways it could be wrong, limited or improved**, and test each one (a test that passes shows it holds; one that fails is a fix). Then try to break it: edge cases, source drift (section 5), concurrency of the daily/n8n/Peru collectors, Lima time zone (UTC−5) day boundaries, empty-but-valid inputs, HTTP 200 challenge pages. | The five-ways table is in the PR; each hole found becomes a test that failed before the fix. |
| 4. Retrospect | What would have caught this earlier? Add that guard or test, update section 6 and the relevant `docs/` page. | The new guard has a test. |

Scratch worktrees: `git worktree add <scratch>/wt-<name> <branch> --detach`. Never prototype on the working branch.

## 3. Tests: tautological tests are considered harmful

A test earns its place only if it can fail for a plausible bug.

- **Assert against independent truth**: an archived real response under `python/tests/fixtures/`, a value computed
  by hand (show the arithmetic in a comment), an invariant (ordering, rebasing, idempotence), or an authoritative
  published value. Never assert that the code returns what the code returns (no snapshots generated by the code
  under test, no `assert f(x) == f(x)`, no mocks that echo the expectation).
- **Mutation proof**: for each new test, apply a plausible mutation to the code under test (flip a comparison,
  drop a branch, change a threshold by one step, swap two columns) and confirm the test fails. Say in the PR which
  mutation you tried. A test that survives every mutation you can think of is deleted or rewritten.
- **Thresholds are tested at their edge**: just below, exactly at (watch float rounding; thresholds compare after
  `round(…, 6)`), just above.
- **Every bug fix ships with a test that fails on the old code.** Run it on the old code once to prove it.
- **No skipping, xfail-ing or loosening a test to get green.** If a test is wrong, fix it and say why in the commit.
- Commands:
  ```bash
  cd python && python -m pytest -q -m "not browser"        # parsers, guards, pipeline (offline)
  node --test n8n/test/*.test.mjs                           # n8n workflow libraries
  node n8n/build.mjs --check                                # n8n/dist matches n8n/lib
  cd python && python -m tools.architecture --check         # generated architecture docs are current
  cd python && python -m pytest -q -m browser --site-dir=../public   # Playwright journeys (CI image)
  ```

## 4. chore(lint): cyclomatic-complexity ceiling

**Rule.** Every Python and JavaScript function has a cyclomatic complexity (McCabe v(G)) of **10 or less**, the
limit NIST SP 500-235 *Structured Testing* §2.5 recommends (it allows more only with formal design and a
comprehensive test plan, which this project does not claim). The 734 functions that already exceeded it when the gate
was added are frozen in `config/complexity-baseline.json`: their scores **may only go down** (a ratchet). The ceiling
is a constant in code, so the baseline cannot raise it.

**How it is measured** (chosen after measuring the alternatives; details in `docs/complejidad.md`):

| Option | Why it was rejected or chosen |
|---|---|
| ruff C901 (mccabe) | Rejected: does not count `and`/`or`, comprehensions or conditional expressions (NIST §4.1 counts each short-circuit operator). 453 of the 574 Python functions over 10 would pass. |
| radon / xenon | Rejected as the gate: silently drops methods of classes defined inside functions, does not descend into `assert`, last release 2023. Kept, pinned, as the independent oracle in the test. |
| lizard | Rejected: token-based, attributes JS callbacks inside template literals to the wrong function; misses `?.` and default parameters. |
| Own `ast` counter (Python) | **Chosen**: implements NIST §4.1 exactly, zero dependencies, identical on 3.12 and 3.13, checked against hand-counted control-flow graphs and against radon on every function where the definitions coincide. |
| ESLint `complexity` (JS) | **Chosen**: AST-based, matches hand-counted graphs; pinned in `scripts/lint/package-lock.json`, inline disables switched off. |
| SonarSource cognitive complexity | Not adopted: better readability metric, but no free pinned implementation for both languages, and it is not the test-path count NIST uses. |

**The test for every task and every round** (run before each commit; CI runs the same in the `lint` job):

```bash
npm ci --prefix scripts/lint --ignore-scripts --no-audit --no-fund   # once
cd python
python -m tools.complexity --report 10        # 0 ok · 1 something to fix · 2 could not measure
COMPLEXITY_REQUIRE_JS=1 python -m pytest -q tests/test_complexity.py
python3.11 -m compileall -q -x tests/fixtures enso tools tests      # the Peru collector's minimum Python
```

**When it fails** (each finding names `file:line function`, its score, the ceiling and the fix):

- `NUEVA` / `CRECIÓ` (new over 10, or a listed function grew): split the function — named helpers, a dispatch table
  instead of an `if/elif` chain, guard clauses. Never edit the baseline by hand; `--update` refuses to add or raise.
  This applies to urgent source-drift fixes too: extract the new branch into a helper in the same PR.
- `BAJÓ` / `CUMPLE` / `NO EXISTE` (a listed function improved, now complies, or was removed): run
  `python -m tools.complexity --update` and commit the baseline diff, so the slack cannot be spent later unnoticed.
- Exit 2 after a tool or metric version change (Dependabot bump of ESLint/espree, `PY_METRIC` changed): run
  `python -m tools.complexity --rebaseline` in the same PR and justify every added or raised line in the PR body.

**Commit convention**: changes that only touch the gate, its baseline or its config are `chore(lint): …`.

Known costs (accepted, stated): the baseline is large and the ratchet only stops growth, it does not pay the debt
down by itself; moving a listed function to another file shows as `NO EXISTE` + `NUEVA` (bring it to 10 or less while
moving it); module-level code and class bodies are not measured; the Python interpreter version is not recorded in
the baseline (CI pins 3.12); anonymous JS callbacks are keyed by position, so inserting one earlier renumbers the rest.

## 5. Source drift: assume every source will change without notice

Every upstream here has already changed silently at least once (section 6). Rules:

- **A parse that succeeds is not evidence that it is right.** Compare values with the previous publication
  (`enso/drift.py`), cross-check against an independent source where one exists (ONI/RONI vs ENFEN tables, ICEN
  from IGP vs ENFEN), and range-check physically implausible values.
- **HTTP 200 is not evidence of content.** Anti-bot pages (Imunify360, Cloudflare, Sucuri, Turnstile, …) are
  recognised by `enso/reach.py` and `n8n/lib/classify.js`, which must stay in parity
  (`python/tests/fixtures/reach-parity.json`). **Never evade a challenge**: fall back to the n8n relay, the Peru
  collector or an official mirror, and say so on the site.
- **Servers may serve variants per request** (CENVUL answers in English or Spanish at random). Fetch a source several
  times before concluding its format; parse every variant seen; a date that parses in no variant is a
  `formatError`, never "inactive".
- **A carried copy is not a live read.** Copies the relay carries forward count as down for alerting and are labelled
  on the site.
- **Nothing important is logged at `info` only.** A condition that can hide a data problem for more than a day must
  raise a warning code that opens an issue (`tools/sync_issues.py`), and conditions that persist escalate
  (`enso/persistent.py`, `enso/data/degradacion.json`).
- **Simulate drift before it happens**: run the drift simulator over the archived fixtures
  (`python -m tools.drift_sim`, see `python/tests/test_drift_sim.py`). Every (source, mutation) pair must end LOUD
  (an error or warning code) or BENIGN (same, correctly normalised output); SILENT-WRONG is a bug unless it is in the
  allowlist with a reason.
- **Weekly audit**: `.github/workflows/drift-audit.yml` re-reads the last week of `data-archive`. Reviewed findings go
  in `python/tools/drift_audit_known.json` with a note. How to repeat it by hand: `docs/auditoria-deriva-fuentes.md`.
- When adding a source: archive a real response under `python/tests/fixtures/sources/`, add a parser test against it,
  a fingerprint, a plausibility range, a `stale_days` measured from its real publishing gaps (not guessed), and its
  block/variant behaviour.

## 6. Retrospective: what went wrong in November 2026 and the lesson

| What happened | Why nobody saw it | Lesson (now a rule above) |
|---|---|---|
| 13 WordPress feeds answered Actions with Imunify360 "One moment, please…" and HTTP 200; archived as the feed 38 times | Unknown signature, 200 trusted, logged as `info` | 200 ≠ content; signatures in parity; no `info`-only failures |
| PSL rewrote Niño 3.4 ERSSTv6 history (wrong longitude box fixed silently; up to 0.6 °C) | Fingerprint checked structure only | Compare values with the previous publication |
| ENFEN informe N° 20 printed ICEN Sep-26 +4.98 vs IGP +4.50 | Mismatch detected, but not which value was coherent | Cross-checks must say which side is consistent and why |
| NOAA discussion values switched to relative anomalies with RONI | Field name implied weekly traditional values | Label the basis of every quoted number |
| CENVUL served English or Spanish at random; Spanish dates unparsed; 10 alerts merged into 2 | Parser tested on one variant | Fetch several times; test every variant |
| Inactive-feed thresholds guessed; one domain reused for unrelated content | No measurement of real gaps | Measure thresholds from archive history |
| DHN PDFs behind Turnstile | Fallback existed, but nobody knew it was carrying the load | Find an official alternative channel (gob.pe) and alert when only a stale copy remains |
| Relay carried yesterday's copy while the source returned HTTP 500 | Carried copy indistinguishable from a live read | Carried ≠ live |
| PTWC exercise PACWAVE26 shown as a tsunami warning | Test messages not filtered | Filter exercises/tests explicitly, with a fixture |
| Threshold comparisons failed on exact float values | No edge tests | Test thresholds at their edge; round before comparing |

## 7. Fail verbose, with clear diagnostics

- Errors name **what** (source id, URL, file:line or function), **expected vs got** (with a short excerpt of the
  offending input), **why it matters** (what on the site is affected) and **what to do next** (the doc or command).
- Exit codes mean something and are documented (e.g. `tools.drift_audit`: 0 nothing new, 1 findings, 2 could not
  audit). "Could not check" is never reported as "nothing found".
- Warning codes are stable, documented in `docs/operaciones.md`, and map to one GitHub issue each.
- Prefer failing the job over publishing a value you cannot vouch for; when the site must still publish, it labels
  the value (provisional, carried copy, stale, relay) instead of hiding the doubt.

## 8. Repository rules for agents

- Work on the branch you were given; never push to `main` or rewrite shared history.
- Generated files are regenerated, never hand-merged: `node n8n/build.mjs`, `python -m tools.architecture`.
- Dev tools are pinned in `python/requirements-dev.txt`; CI runs Python 3.12 and Node 22.
- Don't put secrets or personal data in commits, fixtures or requests to outside services.
- Every trade-off goes in the PR description (section 1.4).

## 9. Domain rules learned the hard way

- **Indices and thresholds cite their institution.** Basin indices (ONI, RONI, Niño 3.4) use NOAA CPC's ±0.5 °C;
  the coast (Niño 1+2, ICEN) uses ENFEN Nota Técnica 01-2024, neutral range [−0.7, +0.5] (`signals.coastal_tone`).
  Every series' `climatology` states the base its institution really uses: RONI fixed 1991–2020; ONI and ICEN
  centred 30-year bases renewed every 5 years. Provisional values (ICENtmp, the last RONI months) are labelled as such.
- **Identity keys never come from raw feed fields.** Use `news.identity_key` / `news.canonical_link` (fragments kept:
  they distinguish DHN and CENVUL items). A new title on the same link is a revision (`revises`), as with an RSS
  `guid` or an Atom `id`.
- **No locale-dependent parsing.** Never `strptime` with `%A`, `%a`, `%B`, `%b`; use explicit month tables
  (Spanish *setiembre* and *septiembre*, English, abbreviations, NBSP). Never rely on `LC_TIME`.
- **"Today" is Lima's date** (`observatory.run_date`, UTC−5): the 04:37 UTC cron is the previous evening in Lima.
  Raw archive file names stay on the UTC day for continuity.
- **Text decoding**: BOM first, then strict UTF-8, then windows-1252 (`feedparse.text_of`); JSON stays strict UTF-8
  (RFC 8259); gzip without `Content-Encoding` is a loud format change, never silently inflated.
- **Colour and contrast**: WCAG 2.2 AA (4.5:1) is tested from the CSS tokens (`tests/test_expert_review.py`), in both
  dark-theme blocks; warm and cool tints keep the same weight (a diverging scale must not favour one sign).
- **Python 3.11 is the collector's minimum**: no 3.12-only syntax (nested same-quote f-strings); CI compiles with 3.11.
